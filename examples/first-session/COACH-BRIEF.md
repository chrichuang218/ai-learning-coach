# 缓存失效首次体验：教练参考

用户明确选择此首次体验时读取。已有其他读本或主线时先沿用用户现场，不以体验包取代其项目。本文件是教学参考，不要求用户先阅读。

## 锚点与准备

- 仓库与固定 commit 见 [体验入口](README.md)。先检查用户背景、当前工作区和读本目录。
- 优先让 `scripts/first_session.py prepare <新目录>` 建立隔离读本。已有目录只检查，保留修改；源码仓库和学习档案分开。
- 目标为 `test/skills.test.ts` 的 `cache reset makes a newly created skill discoverable`，实现为 `src/skills.ts` 的 `discoverSkills` / `resetSkillCache`。
- 环境准备测试由教练执行，不作为学习者证据。类型编译、目标测试都成功后开始；失败时直接诊断该步骤。

## 当前学习动作

先给一个完整预测：首次扫描空目录后新增 Skill，同进程再次 discover 会得到什么，控制流依据是什么。提供实时源码路径，暂不展示答案和后续任务清单。

用户回答后比较运行证据。卡点可能是 `[]` 也是真值、模块状态跨调用保留、文件变化不会自动使缓存失效。只解释实际出现的缺口，然后让用户重新解释整个短链路。

有余力时在独立读本中临时把 `resetSkillCache` 的清空赋值改成 no-op，先预测哪条断言失败，重新编译并运行同一个精确测试。用户确认观察后恢复原有实现并重新编译到 Green。保留已有修改，不切换或重置用户原项目。

减少提示后的迁移入口是“修改已有 Skill 内容”或“同名项目 Skill 覆盖用户 Skill”。选择一个与用户当前理解最相邻的变化；不要替用户先设计完断言后宣称他已经独立设计。

## 结束与恢复

按实际观察区分预测、执行命令、修改、设计测试等动作，并记录每项获得的帮助。未形成学习证据时只记录必要的续学边界。需要长期状态时用单轨道工作区按需创建，初始能力为未验证。

保存真实 commit、相对路径、symbol 和一个下一动作，具体合同见插件内 `LEARNING-RECORD-FORMAT.md`。新会话先核对最新记录、读本 HEAD 和 symbol，再继续。旧记录保留历史事实，当前入口重新定位。
